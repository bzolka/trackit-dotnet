# Architecture

TrackIt is a small issue tracker: an ASP.NET Core Web API over a SQLite file, plus the tools that
let a coding agent work with it (a CLI and an MCP server in two languages).

## Modules

| Folder | What it is | Talks to |
|---|---|---|
| `src/Api/` | The Web API (minimal API, EF Core, FluentValidation) | the SQLite file |
| `src/Tests/` | xUnit integration tests (`WebApplicationFactory`) | the API, in memory, with a temporary SQLite file |
| `tools/Trackit.Cli/` | `trackit` command-line client; run it with `tools/trackit` | the API over HTTP |
| `tools/Trackit.Mcp/` | MCP server in C# (`ModelContextProtocol`), stdio | the SQLite file, directly |
| `tools/trackit-mcp-py/` | the same MCP server in Python (`mcp`), stdio | the SQLite file, directly |
| `scripts/` | helper scripts: `changes.sh` (merged PRs since a tag), `format.sh` (the format hook) | git, gh, dotnet |
| `.claude/` | the agent configuration: settings and hooks, skills, the reviewer subagent, rules | |

Inside `src/Api/`:

- `Program.cs`: services, the database, seeding, endpoint mapping.
- `Endpoints/IssueEndpoints.cs`: the four endpoints and their request records.
- `Validators/`: one FluentValidation validator per endpoint that takes a body or query parameters.
- `Data/`: the `Issue` entity, `TrackItDb` (DbContext) and `SeedData`.
- `Migrations/`: generated by `dotnet ef migrations add`; never edited by hand.
- `DotEnv.cs`: finds the repository root and reads `.env`.

## Data model

One table, `Issues`:

| Column | Type | Notes |
|---|---|---|
| `Id` | integer | the issue number, shown as `#41` |
| `Title` | text, ≤ 200 | required |
| `Description` | text, ≤ 4000 | may be empty |
| `Status` | text | `open`, `in progress` or `closed` |
| `Label` | text, nullable | `bug` or `feature`; exists for the CLI's `--label` |
| `CreatedAt` | text (UTC timestamp) | EF Core's SQLite format |

The sample issues (#37-#45 and #57) are inserted when the API starts with an empty database.

## Request flow

```
tools/trackit search login ──HTTP──▶ GET /issues?q=login ──▶ validator ──▶ EF Core ──▶ data/trackit.db
                                                                                         ▲
Claude Code ──stdio (MCP)──▶ Trackit.Mcp or trackit-mcp-py: search_issues ──plain SQL────┘
```

The API owns the schema: it creates the database and applies the migrations on start. The MCP servers
open the existing file and fail with a clear message if it does not exist yet.

**A schema change must be mirrored in both MCP servers.** They do not use EF Core; they query the
`Issues` table by column name in `tools/Trackit.Mcp/IssueDb.cs` and `tools/trackit-mcp-py/db.py`.
Change both, and check that `search_issues` still returns the same result in each.

## Settings

All programs read `.env` in the repository root (copy `.env.example`). Real environment variables win.

| Setting | Default | Used by |
|---|---|---|
| `TRACKIT_DB` | `data/trackit.db` (relative to the repository root) | API, both MCP servers |
| `TRACKIT_API_URL` | `http://localhost:5000` | CLI |

## Where the agent configuration lives

```
CLAUDE.md                 project knowledge, loaded every session (imports docs/style.md)
CLAUDE.local.md           your notes, git-ignored (example: CLAUDE.local.md.example)
src/Api/CLAUDE.md         API-layer knowledge, loaded when working in src/Api/
.mcp.json                 the two MCP servers (trackit, trackit-py)
.claude/settings.json     hooks, MCP approval
.claude/skills/           release-notes, api-conventions, trackit-issues
.claude/agents/           code-reviewer
.claude/hooks/            protect-files.sh
.claude/rules/db.md       database conventions, loaded with migrations and SQL files
.claude/plugins/          trackit-toolkit: the same pieces packaged as a plugin
```
